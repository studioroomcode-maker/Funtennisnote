# FTN 생성 공통 규칙 — 모든 모델·엔진 적용 (2026-08-27 사용자 지시)

이 규칙은 **모든 생성 엔진에 예외 없이 적용**된다: ComfyUI(z-image, MiniMax H3), Higgsfield(Nano Banana, Kling, Seedance, Cinema Studio), Google Flow(Omni Flash, Veo), 그리고 향후 추가되는 모든 이미지·영상 모델. **본 문서의 1~6번 전 항목이 엔진 구분 없이 적용된다** — 어떤 엔진으로 생성하든 레퍼런스 참조, 로고 정책, 테돌이 등장, 설명형 3D 장면 설계, 인-신 텍스트+검증 규칙을 동일하게 지킨다.

## 1. 레퍼런스 폴더 필수 참조

**이유(사용자 명시):** 테니스 코트·네트·공은 기하가 복잡해서 참고 자료 없이 생성하면 반드시 틀린다. 실제로 텍스트 프롬프트만으로 생성한 결과물에서 공의 솔기 무늬 형태와 코트 라인 디자인이 다수 잘못되어 있었다. 따라서 공·코트·네트·라켓이 등장하는 모든 컷은 형태 레퍼런스가 필수다.

**QC 필수 항목:** 생성 결과 검수 시 ① 공의 흰 곡선 솔기가 실제 테니스공 형태인지(야구공·농구공 무늬 금지) ② 코트 라인 구성(베이스라인·서비스 박스·센터라인)이 실제 규격 배치인지 ③ 네트 구조를 반드시 확인한다.
- 어떤 엔진이든 이미지·영상 생성 시 `reference/` 폴더의 파일을 조건 이미지(레퍼런스/ingredient/start-image 등 해당 엔진의 방식)로 반드시 참고시킨다.
  - `basicrefer_tennisball.png` / `basicrefer_court.png` / `basicrefer_net.png` / `basicrefer_racket.png` — 해당 사물이 등장하는 컷의 형태·비율 기준
  - `tedori_character_sheet_final.png` — 테돌이 등장 컷의 캐릭터 기준
- 엔진별 적용 방법:
  - ComfyUI: `TextEncodeZImageOmni`의 `image1`~`image3` 입력(vae 연결 필요), 영상은 `minimax_h3_ref2va`(`MiniMaxH3ReferenceToVideo`)
  - Higgsfield CLI: `--image-references` 플래그
  - Google Flow: Ingredients/Frames 첨부

## 2. 로고·브랜드 정책
- 장면에 광고판·간판·로고·브랜드가 필요하면 반드시 `reference/`의 tennisnote 로고를 사용한다.
  - 어두운 배경: `테니스노트로고White.png` / 밝은 배경: `테니스노트로고.png` / 아이콘만: `tennisnote_icon.png`
- 임의의 가짜 브랜드·글자 생성 금지. 생성 단계에서 로고를 넣기 어려우면 빈 판으로 생성하고 후반 합성으로 로고를 얹는다.
- 마지막 컷 하단의 로고 워터마크(`테니스노트로고White.png`, 페이드인)는 매 에피소드 유지.

## 3. 테돌이 등장 규칙
- **한 에피소드(화수)당 최소 1회** 테돌이를 반드시 등장시킨다.
- 역할: 화면 가장자리의 엑스트라 또는 내용을 설명하는 캐릭터. 핵심 피사체·인포그래픽을 가리지 않는 크기(프레임 높이 15~20%).
- 캐릭터 기준은 `tedori_character_sheet_final.png` (구형 몸, 대칭 눈, 작은 입, 흰 곡선 솔기 2줄, 짧은 팔다리) — 반드시 레퍼런스로 걸고 생성한다.

## 4. 기존 절대 규칙 유지
- 생성 이미지·영상에 글자·숫자·자막·화살표·다이어그램 선 금지 (인포그래픽은 후반 오버레이 전용).
- 무음 생성, 스타일: 신비한 건축사전 계열 포토리얼 아크비즈 (항공뷰·클린 3D 설명 모델).
- 주석 모션그래픽: 빨간 한글 키워드 헤드라인 + 핀 태그 + 치수선 (tools/ 및 scratchpad anno.py 스타일).

## 5. 장면 설계 원칙 — 설명형 3D 모션그래픽 (2026-08-27 추가 · **모든 모델·엔진 공통 적용**)

영상의 본체는 "예쁜 장면 + 주석"이 아니라 **내용을 분석·해석·설명하는 3D 인포그래픽 모션그래픽**이어야 한다 (신비한 건축사전 방식).

- 각 컷은 문장의 원리를 **장면 자체의 동작으로 증명**해야 한다:
  - **단면(cutaway)**: 공이 실제로 갈라지며 내부 층이 드러나는 동작
  - **분해(exploded view)**: 구조가 공중에서 부품으로 분리됐다가 재조립
  - **시뮬레이션**: 원리가 실제로 작동하는 모습 (예: 흰 공과 흰 라인의 휘도가 겹쳐 소실되는 과정, 시인성 비교 테스트가 눈앞에서 진행)
  - **측정/계측**: 카메라가 클린 3D 설명 모델 위를 이동하며 치수·기간·규격이 장면에 맞춰 드러남
- 미학보다 **설명력 우선**: "무엇이 보이는가"가 아니라 "무엇이 증명되는가"로 컷을 설계한다.
- 구현: 이미지 프롬프트 단계에서 단면·분해·시뮬레이션 상태를 명시적으로 스테이징하고, H3 모션 프롬프트로 그 동작(갈라짐·분리·작동)을 지시한다. 후반 주석(빨간 헤드라인·핀·치수선)은 3D 동작에 앵커링해 보조한다.
- 색 관리: 모든 이미지 프롬프트에 공통 스타일 블록(채도·조명·그레이드)을 강제하고, 조립 시 컷별 채도 곡선(과거 저채도 → 현재로 갈수록 상승)을 통일 그레이딩으로 적용한다.

## 6. 텍스트·인포그래픽 인-신(in-scene) 생성 원칙 (2026-08-27 사용자 지시 — 기존 규칙 대체 · **모든 모델·엔진 공통 적용**)

**후반 합성으로 따로 얹는 그래픽·텍스트는 금지한다** (분리감 때문에 저품질로 보임). 헤드라인·라벨·치수·연도 등 모든 인포그래픽 요소는 **생성 단계에서 장면 안에 직접 제작**한다 — 3D 공간에 물리적으로 존재하는 것처럼 (표지판·측정 눈금·조각된 숫자·장면에 앵커된 다이어그램).

- 이 원칙은 기존의 "생성 이미지·영상에 글자 금지" 규칙을 **의도된 라벨에 한해 대체**한다. 임의의 배경 글자·가짜 브랜드·의미 없는 문자는 여전히 금지.
- **글자 검증 필수**: 컷마다 생성된 텍스트의 글리프 무결성을 반드시 검수한다.
  - 확인 항목: 철자·글자 형태 왜곡(특히 한글 자모 깨짐), 좌우 반전, 중복 문자, 흐릿함
  - 검증 방법: 프레임 확대 육안 검수 + 가능하면 OCR 대조. 영상은 시작·중간·끝 3개 프레임에서 텍스트 유지 여부 확인 (H3 등 영상 모델이 프레임 진행 중 글자를 뭉갤 수 있음)
  - 깨졌으면 시드/문구를 바꿔 재생성. 반복 실패 시에만 예외적으로 후반 합성 폴백 허용
- 팁: 짧은 텍스트(숫자·연도·영단어 1~3개)가 성공률이 높다. 한글은 단어 수를 최소화하고 검증을 더 엄격히 한다.
